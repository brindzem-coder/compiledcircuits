Ще не виконані: позиційні обходи, час tick, час scan, пакети/байти при руйнуванні, пам'ять. Для порівняння зафіксувати розміри схем, кількість мереж/гравців, налаштування та умови. Відсутність інструментування або середовища позначати як недоступну перевірку, а не як нульове значення.

1. Підготувати діагностичний збір та експорт відсутніх показників; перевірити, що вимкнена діагностика не змінює поведінку.
2. Створити окремий творчий плоский світ Performance Baseline із дозволеними командами; зафіксувати seed, gamerules, схеми, координати й завантажені чанки. New World та його резервну копію не використовувати для руйнівних benchmark.

4. Сценарії: порожня ділянка, одна велика мережа, багато малих із порівнянною сумарною місткістю, масове пошкодження/ремонт, сторонні блоки. Точні розміри й генератор ще потрібно підготувати.
5. Для steady-state: після завершення генерації та завантаження чанків 60 секунд прогріву, потім 60 секунд вимірювання, 3 повтори. Для окремих операцій записувати всю операцію до завершення черг, не обривати на фіксованій секунді. Тривалості — методика збору, а не пороги правильності.

7. Перед повтором руйнування/ремонту відновлювати однаковий підготовлений стан. Профіль CPU збирати окремо від мінімально інструментованого вимірювання часу; не порівнювати різні режими профілювання.
